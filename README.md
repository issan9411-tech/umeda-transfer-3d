# 梅田のりかえ3D — Umeda Transfer Simulator

大阪・梅田エリアの 8 駅について、**ホームからホームまでの最適な乗り換えルート**を 3D の歩行者ネットワーク上で計算・可視化するシミュレーターです。

| 駅 | 事業者・路線 | ホーム階 |
| --- | --- | --- |
| JR大阪駅（1〜11番） | 環状線・JR京都線・JR神戸線・JR宝塚線・特急 | 2階（高架） |
| JR大阪駅 うめきたエリア（21〜24番） | はるか・くろしお・おおさか東線 | 地下2階（約−15m） |
| 阪急大阪梅田 | 京都線・宝塚線・神戸線 | 3階（頭端式） |
| 阪神大阪梅田 | 阪神本線 | 地下（頭端式・改札は地下1階） |
| 梅田 | Osaka Metro 御堂筋線 | 地下1階 |
| 東梅田 | Osaka Metro 谷町線 | 地下2階 |
| 西梅田 | Osaka Metro 四つ橋線 | 地下2階 |
| JR北新地 | JR東西線 | 地下約24m |

## できること

- **ルート検索**：出発ホーム（または駅全体）と到着ホームを選ぶと、推奨ルートと性格の異なる代替ルート（例：ホワイティうめだ経由／阪急三番街経由）を最大 3 本表示します。
- **おすすめ乗車位置**：出発ホームのどの位置で降りれば乗り換えが最短になるかを同時に計算します（「前方・中ほど・後方」相当の位置名で表示）。
- **歩き方の違い**：標準・急ぎ・大きな荷物・ゆっくり・段差なし（車いす・ベビーカー）の 5 プロファイル。段差なしではエレベーターのみを使います。
- **条件**：時間／距離／楽さ（階段・人混み回避）の優先、平日・土休日と時刻による混雑、雨の日モード（屋外区間を回避）、歩行速度。
- **3D ウォークスルー**：「このルートを3Dで歩く」または ▶ を押すと、カメラが歩行者について実際に構内を歩いていきます。
  - 視点：歩行者視点（後方）・一人称・俯瞰で追従・全体表示のまま
  - 通路の床と壁、地下通路の天井照明、階段の段、エスカレーター、ガラスのエレベーター、改札機の列、ホームの点字ブロック、発着ホームに停まる電車を 3D で表示
  - 地下街は天井・店舗・看板のある囲まれた通路、駅はホーム・大屋根・線路・架線まで再現
  - 歩行者は手足が動く人体モデル（服装・体格・荷物・スマホ・スーツケースがばらばら）。群衆シミュレーションの人も同じモデルで歩き、階段では上り下りの姿勢になります
  - 時刻に合わせて太陽の位置・空の色・影が変わり、夜はビルの窓や街灯が灯ります（地下は駅の照明のみ）
  - 周辺のビルを実際の高さで表示し、道路・街路樹・走る車・HEP FIVE の観覧車も再現。歩行者を隠すビルは自動で半透明になります
  - 床に黄色い誘導ライン（進行方向の矢印付き）、次の案内をサインボードとして表示
  - 画面上部に「今の案内・次の案内・現在の階・残り距離と時間」、右下にミニマップ（北が上）
  - 再生速度 ×1〜×30、Esc キーで全体表示に戻る
- **3D 表示**：階ごとの表示切替（エレベーターの階数ボタン風）、高さ強調、視点プリセット（俯瞰・北から・断面・真上）、ホームをクリックして出発／到着に設定。
- **群衆シミュレーション**：駅の利用者数に応じた OD で歩行者エージェントを発生させ、通路ごとの密度をヒートマップ表示。測定した密度を経路計算に反映することもできます。
- **乗換時間表**：全 56 組の駅間乗換時間（標準／最短）を一覧。セルを押すとその経路を 3D 表示します。

## 使い方

```bash
cd umeda-transfer-3d
npm install
npm run dev          # http://localhost:5173/
npm test             # アルゴリズム・データ整合性・公表値との比較テスト
npm run build        # dist/ に静的サイトを出力
npm run build:single # dist-single/index.html（1ファイルで完結する版）を出力
```

## 計算モデル

- **ネットワーク**：ホームの乗車位置・改札・通路・階段・エスカレーター・エレベーター・横断歩道をノード／リンクとした 3 次元グラフ（データに書く地点は約 280。階段の踊り場や乗り口を展開すると約 1,300 ノード、1,500 リンク）。座標は大阪駅を原点とするローカル座標（m）で、東が +x、南が +z、上が +y。
- **経路探索**：多始点ダイクストラ法。出発ホームの全乗車位置を始点にすることで、最短ルートと最適な乗車位置が同時に求まります。代替ルートは使用した通路のコストを段階的に上げて再探索し、重なりが 65% 以下のものだけを採用します（Yen の K 最短路も実装し、テストで総当たりと一致することを確認）。
- **改札のルール**：出発駅・到着駅以外の事業者の改札内は通り抜けできません（JR大阪駅とうめきたエリアは同一の改札内として扱います）。
- **移動時間**：
  - 平地：標準 1.3 m/s（プロファイルで変更）
  - 階段：上り 0.30 m/s、下り 0.38 m/s（鉛直速度）
  - エスカレーター：傾斜 30°、0.5 m/s（立ち止まって乗る想定）
  - エレベーター：平均待ち 40 秒＋乗降 10 秒
  - 改札：3 秒
  - 横断歩道：信号待ち 35〜40 秒
- **混雑**：時間帯別の需要係数と通路の混雑度から歩行者密度を推定し、Weidmann の速度–密度関係で歩行速度を落とします。群衆シミュレーションでは各エージェントが実際の密度に応じて減速します。

## 構内の立体モデル（歩ける空間としての整合性）

データに書くのは「どこからどこへ階段・エスカレーター・エレベーターでつながっているか」だけです。実際の形は `src/data/builder.ts` が組み立てます。

- **階段**：勾配約28°（踏面30cm・蹴上16cm）で、4mの高さごとに奥行き1.6mの踊り場を設けます（建築基準法施行令24条）。
- **エスカレーター**：30°。
- **エレベーター**：垂直のシャフトで、扉は通路側に開きます。
- **配置の決め方**：調査で向きが分かっている階段は、データに「上りの向き」と「どちらの端を通路に合わせるか（上端・下端）」を書きます。それ以外は、上下どちらの階でも通路の中心線や他の階段の吹き抜けと重ならないように、向きと位置を探索して決めます。島式ホームでは、ホームの端から1.6mの歩行線の脇に階段を置きます。
- **吹き抜け**：上の階の床は、階段の上の方（床下に頭上2.6mが取れない部分）だけが開口になります。それより下では上の階の床が階段の上を覆うので、別の階段や通路を重ねて配置できます。
- **乗り降りの通路**：階段の昇り口・降り口へは、最後の1.2mをまっすぐ進む通路でつなぎます。吹き抜けや段の下は通らず、回り込みます。
- **壁**：`src/render/walk-space.ts` が、通路・広場・ホーム・階段・シャフトを「人が通る空間」（床と頭上2.3m）としてまとめます。壁・ガラス・店舗・柱・改札機・駅の構造物・ビルの外壁は、この空間にかかる部分を切り取って描きます（通路が交わる所は開口、上を通路が通る天井や床板はその部分だけ抜きます）。ビルには通路が入る所に入口の枠が付きます。
- **群衆**：吹き抜けの横では落ちない幅の中だけを、ホームでは端から1m以上内側を歩きます。改札は改札機の間の通路を通ります。

`tests/walk-geometry.test.ts` は、歩行者と群衆が全ルートを歩いたときに、通路・駅・ビルのどの壁も抜けないか・床があるか・天井や床板が体を貫かないかを毎回検査します。

### 駅の配置（調査にもとづく主な点）

- **JR大阪駅**：ホーム（1・2番〜11番）と線路は OpenStreetMap の地図（Overture Maps 経由、© OpenStreetMap contributors, ODbL）に合わせています。線路は駅の中を方位58.4°（東北東）にまっすぐ通り、ノースゲートビルの南面・サウスゲートビルの北面もこれと平行なので、線路方向と直角方向の「駅座標」で各ホーム・階段・改札・コンコースを置いています（各階段の列は線路と直角に並びます）。ホーム上の階段は西から 西口・桜橋口・中央口・連絡橋口・御堂筋口 の順。西口はホーム西端から西向きに下りて正面が改札、御堂筋口は東向きに下りて右へ進むと南口改札。桜橋口は階段のみで中2階通路を経由します。中央口は改札（中央コンコースの西側）を入ってすぐのエスカレーターを西向きに上ります。3階の連絡橋口は改札の東側のコンコースから、ホーム中ほどへ西向きに下ります。
- **中央の縦のつながり**：1階の中央コンコース、3階の南北連絡橋、ノースゲートビルのアトリウム広場（2階、暁の広場の真上）は、線路と直角な一本の線上（大屋根の中央）に重なっています。中央南口の地下への階段はコンコースの中にあり、南向きに下りて大丸の地下から阪神へ続きます。駅前の横断歩道は地図の横断歩道の位置にあり（中央南口前は交差点東側、御堂筋口前は高架下で国道176号を渡る1本）、御堂筋南口と阪神の間は梅田新歩道橋で渡ります。
- **梅田（御堂筋線）**：御堂筋・国道176号の下を北北西に走り、北改札はJR御堂筋北口と阪急うめだ本店の間の道路の下にあります。北改札・南改札の階段はホームの端から、中改札の階段はホームの西側から上がります。
- **うめきた・北新地・阪急・阪神・東梅田・西梅田**も、ホームと改札・出入口の位置は OpenStreetMap に、ホームの左右・階段の向き・改札と通路のつながりは調査結果に合わせています。うめきたの地下ホームは実際にはわずかに曲がっていますが、方位27.5°（北北東）の直線で近似しています（ずれは数 m）。阪急の3つのホーム群は方位約350°で平行、阪神は方位約59°、北新地は方位約94°です。
- **地上・デッキ・地下街**：1階の屋外の通路は歩道や広場の上を通り（建物の中を通るのは屋内通路だけ）、横断は地図の横断歩道の位置で車道を渡ります。2階デッキと梅田新歩道橋は地図の歩道橋の上、地下街（ホワイティうめだ・ディアモール大阪など）は地図に地下通路がある所ではそれに沿っています。

## 検証

`tests/umeda.test.ts` で、公表・案内されている乗換時間とモデルの値を比較しています（平日 11 時・混雑なし・標準の歩き方）。

| 区間 | 公表値 | 許容範囲（モデル） |
| --- | --- | --- |
| JR環状線ホーム → うめきた23・24番 | 約8分（JR西日本） | 5.5〜10.5分（標準で約6分、大きな荷物で約8分） |
| 阪急3階改札 → JR御堂筋口 | 約7分 | 6〜11分 |
| 阪急3階改札 → 御堂筋線北改札 | 約5分 | 4.5〜9分 |
| JR中央口 → 北新地 | 約7〜12分 | 7〜13分 |
| 北新地 → 御堂筋線梅田 | 約9分 | 5.5〜11分 |
| 北新地 ⇔ 西梅田 | 1〜3分 | 2〜6分 |

ほかに、ネットワークの構造検査（改札を通らずに改札内へ入れる通路がないか、全駅間が「段差なし」でも到達できるか等）を行っています。

## データについて（重要）

- 位置・高さ・通路長は、公開情報と推定に基づく**概略モデル**です（誤差は数十 m 程度）。実際の移動では駅の構内図・案内表示を優先してください。
- 各駅の階段・改札・通路の位置と向きは、ウェブ調査（鉄道会社の構内案内・乗換案内・地図サイトなど）で確認できた事実に合わせています。確認できなかった部分（ホームの深さ、エレベーターの位置、一部の通路の形、周辺の道路やビルの細かな位置など）は推定です。
- 工事による一時的な通路閉鎖や、商業施設の営業時間は考慮していません。

## ディレクトリ構成

```
src/
  core/     グラフ・コストモデル・探索（Dijkstra / Yen / 代替ルート）・乗換表・検証
  data/     梅田のネットワークデータ（builder.ts の DSL で記述）
  sim/      群衆シミュレーション
  render/   three.js による 3D 表示
  ui/       画面・操作
tests/      Vitest
```

### データの編集

`src/data/*.ts` は `NetBuilder` の DSL で書かれています。

```ts
b.node('hk_3f_in', 'gate', '阪急 3階改札口', [34.70454, 135.49856], '3F', { station: 'hankyu', paid: true, y: 11 });
b.gate('hk_3f_in', 'hk_3f_out', '阪急 3階改札口', { busy: 3 });
b.vertical('hk_3f_out', 'hk_1f_foot', ['stairs', 'esc', 'elev']);
b.walk('f_dm_c', 'f_dm_s', { name: 'ディアモール大阪', indoor: true });
```

座標は緯度経度（WGS84）でもローカル座標でも指定できます。変更後は `npm test` で構造検査と公表値との比較を確認してください。
