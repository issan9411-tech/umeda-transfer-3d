# 梅田のりかえ3D — Umeda Transfer Simulator

大阪・梅田エリアの 8 駅について、**ホームからホームまでの最適な乗り換えルート**を 3D の歩行者ネットワーク上で計算・可視化するシミュレーターです。

| 駅 | 事業者・路線 | ホーム階 |
| --- | --- | --- |
| JR大阪駅（1〜11番） | 環状線・JR京都線・JR神戸線・JR宝塚線・特急 | 2階（高架） |
| JR大阪駅 うめきたエリア（21〜24番） | はるか・くろしお・おおさか東線 | 地下2階（約−15m） |
| 阪急大阪梅田 | 京都線・宝塚線・神戸線 | 3階（頭端式） |
| 阪神大阪梅田 | 阪神本線 | 地下1階（頭端式） |
| 梅田 | Osaka Metro 御堂筋線 | 地下1階 |
| 東梅田 | Osaka Metro 谷町線 | 地下2階 |
| 西梅田 | Osaka Metro 四つ橋線 | 地下2階 |
| JR北新地 | JR東西線 | 地下約24m |

## できること

- **ルート検索**：出発ホーム（または駅全体）と到着ホームを選ぶと、推奨ルートと性格の異なる代替ルート（例：ホワイティうめだ経由／阪急三番街経由）を最大 3 本表示します。
- **おすすめ乗車位置**：出発ホームのどの位置で降りれば乗り換えが最短になるかを同時に計算します（「前方・中ほど・後方」相当の位置名で表示）。
- **歩き方の違い**：標準・急ぎ・大きな荷物・ゆっくり・段差なし（車いす・ベビーカー）の 5 プロファイル。段差なしではエレベーターのみを使います。
- **条件**：時間／距離／楽さ（階段・人混み回避）の優先、平日・土休日と時刻による混雑、雨の日モード（屋外区間を回避）、歩行速度。
- **3D ウォークスルー**：「このルートを3Dで歩く」または ▶ を押すと、カメラが歩行者について実際に構内を歩いていきます。
  - 視点：歩行者視点（後方）・一人称・俯瞰で追従・全体表示のまま
  - 通路の床と壁、地下通路の天井照明、階段の段、エスカレーター、ガラスのエレベーター、改札機の列、ホームの点字ブロック、発着ホームに停まる電車を 3D で表示
  - 床に黄色い誘導ライン（進行方向の矢印付き）、次の案内をサインボードとして表示
  - 画面上部に「今の案内・次の案内・現在の階・残り距離と時間」、右下にミニマップ（北が上）
  - 再生速度 ×1〜×30、Esc キーで全体表示に戻る
- **3D 表示**：階ごとの表示切替（エレベーターの階数ボタン風）、高さ強調、視点プリセット（俯瞰・北から・断面・真上）、ホームをクリックして出発／到着に設定。
- **群衆シミュレーション**：駅の利用者数に応じた OD で歩行者エージェントを発生させ、通路ごとの密度をヒートマップ表示。測定した密度を経路計算に反映することもできます。
- **乗換時間表**：全 56 組の駅間乗換時間（標準／最短）を一覧。セルを押すとその経路を 3D 表示します。

## 使い方

```bash
cd umeda-transfer-3d
npm install
npm run dev          # http://localhost:5173/
npm test             # アルゴリズム・データ整合性・公表値との比較テスト
npm run build        # dist/ に静的サイトを出力
npm run build:single # dist-single/index.html（1ファイルで完結する版）を出力
```

## 計算モデル

- **ネットワーク**：ホームの乗車位置・改札・通路・階段・エスカレーター・エレベーター・横断歩道をノード／リンクとした 3 次元グラフ（約 230 ノード、410 リンク）。座標は大阪駅を原点とするローカル座標（m）で、東が +x、南が +z、上が +y。
- **経路探索**：多始点ダイクストラ法。出発ホームの全乗車位置を始点にすることで、最短ルートと最適な乗車位置が同時に求まります。代替ルートは使用した通路のコストを段階的に上げて再探索し、重なりが 65% 以下のものだけを採用します（Yen の K 最短路も実装し、テストで総当たりと一致することを確認）。
- **改札のルール**：出発駅・到着駅以外の事業者の改札内は通り抜けできません（JR大阪駅とうめきたエリアは同一の改札内として扱います）。
- **移動時間**：
  - 平地：標準 1.3 m/s（プロファイルで変更）
  - 階段：上り 0.30 m/s、下り 0.38 m/s（鉛直速度）
  - エスカレーター：傾斜 30°、0.5 m/s（立ち止まって乗る想定）
  - エレベーター：平均待ち 40 秒＋乗降 10 秒
  - 改札：3 秒
  - 横断歩道：信号待ち 35〜40 秒
- **混雑**：時間帯別の需要係数と通路の混雑度から歩行者密度を推定し、Weidmann の速度–密度関係で歩行速度を落とします。群衆シミュレーションでは各エージェントが実際の密度に応じて減速します。

## 検証

`tests/umeda.test.ts` で、公表・案内されている乗換時間とモデルの値を比較しています（平日 11 時・混雑なし・標準の歩き方）。

| 区間 | 公表値 | 許容範囲（モデル） |
| --- | --- | --- |
| JR環状線ホーム → うめきた23・24番 | 約8分（JR西日本） | 5.5〜10.5分（標準で約6分、大きな荷物で約8分） |
| 阪急3階改札 → JR御堂筋口 | 約7分 | 6〜11分 |
| 阪急3階改札 → 御堂筋線北改札 | 約5分 | 4.5〜9分 |
| JR中央口 → 北新地 | 約7〜12分 | 7〜13分 |
| 北新地 → 御堂筋線梅田 | 約9分 | 5.5〜11分 |
| 北新地 ⇔ 西梅田 | 1〜3分 | 2〜6分 |

ほかに、ネットワークの構造検査（改札を通らずに改札内へ入れる通路がないか、全駅間が「段差なし」でも到達できるか等）を行っています。

## データについて（重要）

- 位置・高さ・通路長は、公開情報と推定に基づく**概略モデル**です（誤差は数十 m 程度）。実際の移動では駅の構内図・案内表示を優先してください。
- JR大阪駅（うめきたエリアを含む）、JR北新地、阪急大阪梅田はウェブ調査の結果を反映しています。阪神大阪梅田、Osaka Metro の 3 駅、地下街（ホワイティうめだ・ディアモール大阪など）は、調査の途中で検索上限に達したため一般的な知識に基づく推定で、未検証です。
- 工事による一時的な通路閉鎖や、商業施設の営業時間は考慮していません。

## ディレクトリ構成

```
src/
  core/     グラフ・コストモデル・探索（Dijkstra / Yen / 代替ルート）・乗換表・検証
  data/     梅田のネットワークデータ（builder.ts の DSL で記述）
  sim/      群衆シミュレーション
  render/   three.js による 3D 表示
  ui/       画面・操作
tests/      Vitest
```

### データの編集

`src/data/*.ts` は `NetBuilder` の DSL で書かれています。

```ts
b.node('hk_3f_in', 'gate', '阪急 3階改札口', [34.70495, 135.49855], '3F', { station: 'hankyu', paid: true, y: 11 });
b.gate('hk_3f_in', 'hk_3f_out', '阪急 3階改札口', { busy: 3 });
b.vertical('hk_3f_out', 'hk_1f_foot', ['stairs', 'esc', 'elev']);
b.walk('f_dm_c', 'f_dm_s', { name: 'ディアモール大阪', indoor: true });
```

座標は緯度経度（WGS84）でもローカル座標でも指定できます。変更後は `npm test` で構造検査と公表値との比較を確認してください。
